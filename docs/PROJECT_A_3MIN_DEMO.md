# Project A｜约 3 分钟分段演示脚本

本脚本**不调用聊天模型**。三段使用同一隔离企业，但不是同一次真实模型端到端运行：第一段是 2026-10-21 真实 Graph/API 成功响应的 React 回放；第二段读取随后由受控 Provider＋真实 JWT/API＋隔离 PG 保存的另一案件调查记录；第三段实际操作申请、审核与站内通知。原始运行证据仅留本地，边界见[脱敏基线](PROJECT_A_BASELINE_EVIDENCE.md)与[持久化验收](PROJECT_A_INVESTIGATION_RUN_ACCEPTANCE.md)。

## 录屏前准备（不计入 3 分钟）

1. 按[隔离演示准备](PROJECT_A_DEMO.md#从新环境准备隔离演示)核对服务与原演示数据。2026-10-22 本地只读检查：3110／8125 可登录且申请列表可读，但该旧 API 对调查历史 GET 返回 405，**不能作为刷新恢复展示入口**；3112／8126 的受控页面、认证和调查历史可用，两份报告可按授权读取。端口可用性只代表检查当时，不要把历史 `READY` 当作永久服务。保留 `scripts/investigation_allocation_demo_state.json`、`scripts/action_request_demo_state.json` 与本地保存的成功响应；缺任一文件则该段标“需核对”，不要临时重跑模型或重建数据。
2. 在仓库根目录启动 `node scripts/investigation_allocation_replay_proxy.cjs`，只将 **3111** 用于保存响应回放。该代理只在通过现有认证与企业／工作区检查后返回保存结果，调查 POST 不转发到 8125。先查看 `http://127.0.0.1:3111/__project_a_replay`，确认 `mode=local_saved_response`；若本地证据缺失，代理会拒绝启动。
3. 从被忽略的 `scripts/action_request_demo_state.json` **本地**读取 `emails.member`、`emails.admin` 和 `password`，不在录屏或文档中展示凭据／完整 Token。成员分别登录 3111 和 3112；管理员在另一浏览器配置文件登录 3112。企业、原分配案件和 SOP 工作区从被忽略的 `scripts/investigation_allocation_demo_state.json` 读取。2026-10-22 用户在普通 PowerShell 对本项目容器、宿主 5433 与 allocation schema 做只读核查，得到 `ragforge_day6_test|1`：案件 `7beb2d8e-7ec6-4aef-b48e-3308a8881a21` 及关联订单属于演示企业 `d6f90c90-01b5-42de-81f5-5d4e2268aee7`。3112 的受控历史案件则是 `3617a006-21d0-5daa-a5d3-4f95f52f935c`，与分配案件不同；对应保存记录 `1691e8ff-7610-46ef-953a-f56635e74b3a`。受控服务按本地状态锁定同一隔离库的 allocation schema，授权 API 已读回两份保存报告。两个浏览器角色提前就绪；真实模型、CDP、数据库测试都无需运行。

## 画面与讲解词

| 时间 | 页面操作 | 讲解词与证据边界 |
| --- | --- | --- |
| 0:00–0:45 | 成员在 **http://127.0.0.1:3111/investigations**，选择状态文件中的企业、原分配案件与 SOP 工作区，分析时点留空，勾选必需检索，点击一次本地回放提交；代理只返回保存响应，**不会转发调查或调用模型**。展开六部分交接单与技术证据，复制请求标识。 | “这里回放一份已保存的真实 Graph/API 调查响应，不是现在调用模型。该运单发货晚一小时，订单级分配受阻记录与本次发货延迟有关；送达早一小时，整单其他原因和完成情况未知。六条业务事件与 SOP 来源分别校验，建议尚未执行。” |
| 0:45–1:15 | 切到成员的 **http://127.0.0.1:3112/investigations**，在“我的调查记录”选择上述 `3617…` 案件的**受控 `not_found`** 报告；刷新页面后再次从记录中打开。**只读取历史，不点生成按钮**。若该记录或服务当前不可用，展示[持久化验收摘要](PROJECT_A_INVESTIGATION_RUN_ACCEPTANCE.md)并标“现场需核对”，不要新提交。 | “这一段展示持久化读取与刷新恢复，报告来自受控 Provider 加真实 JWT/API/隔离 PG，不是上一段的真实业务报告。两轮手工验收分别确认运行中找回状态、成功后找回报告，且每轮只保存一条记录。” |
| 1:15–2:00 | 成员在 **http://127.0.0.1:3112/action-requests**，手动填入 allocation 状态文件中的**原分配演示案件 ID**（与受控 `not_found` 案件不同），输入客户通知内容并创建，展示申请 ID 与“待人工审核，尚未发送通知”。 | “调查不会自动发通知。申请以企业和提交键去重，服务端从 JWT 确认申请人并校验案件归属。” |
| 2:00–2:35 | 切到已登录的企业 **admin／owner** 浏览器，在同一 **3112/action-requests** 页面批准该申请；展示“已批准，尚未发送通知”。 | “人工审核与审计写入同一事务。批准只授权后续执行，不代表已发送或已执行。” |
| 2:35–3:00 | 管理员显式点击执行，查看关联的站内通知记录与申请的执行状态。 | “执行只创建系统内通知记录；`delivery_status=not_sent`，没有邮件／短信送达或客户收悉证明。重复执行不会新增第二份站内通知。” |

如需展示拒绝，另建一份申请再由管理员拒绝；不要对已批准申请追加第二个决定。完整操作与清理边界见[演示指南](PROJECT_A_DEMO.md)。历史真实调查单次耗时 490.797 秒，因此录屏采用保存结果回放；这不是稳定耗时或性能提升结论。
